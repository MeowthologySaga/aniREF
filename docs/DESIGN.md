# aniREF 설계 문서

> 여러 레퍼런스 영상에서 좋은 키포즈를 뽑아 비교·조합하고, Maya 블로킹에 바로 쓰는 도구.
>
> **Video → Frame → Key Pose → Compare → Combine → Blocking**

이 문서는 초안 브레인스토밍(36개 항목)을 실제 구현 기준으로 다듬은 버전이다.
초안에서 바뀐 점과 그 이유는 [1. 다듬은 결정 사항](#1-다듬은-결정-사항)에 모아두었다.

---

## 0. 범위

| 단계 | 내용 | 상태 |

| **2차** | Onion Skin, Motion Trail, Comparison Board(Compare 모드), Silhouette, Reference↔Playblast 나란히/Overlay/차이 비교, Timing 구간, 프레임 간격 표시, 포즈 연결 검토(앞발/체중발) | ✅ |
| **3차** | Root Motion·검끝 궤적 수치(수동 점 찍기 기반) | ✅ |

초안 대비 MVP로 당겨온 것: **Flipbook 미리보기**(이미지 넘기기라 비용이 거의 없음), **Maya 마커 Export**(시퀀스 데이터에서 바로 나옴).
Root Motion과 검 궤적 분석은 자동 트래킹 없이 **Motion Trail 점 찍기**로 먼저 구현했다(§1.11).

## 1. 다듬은 결정 사항

### 1.1 "프레임"의 정의
- **프레임 N = 영상이 보여주는 N번째 그림** (표시 순서 기준). 시간 × fps 계산이 아니다.
- 그래서 게임 녹화에 흔한 **가변 프레임레이트(VFR)** 영상에서도 번호가 어긋나지 않는다. 시간 표시는 각 프레임의 실제 타임스탬프를 쓴다.
- 내부는 전부 **0부터**. 화면 표시는 설정(`frame_base`)으로 **기본 1부터**(Maya 타임라인과 같게).

### 1.2 소스 fps ≠ 애니 fps
레퍼런스는 60fps인데 Maya 씬은 30fps인 경우가 많다. 그래서 두 가지 프레임을 구분한다.
- **소스 프레임**: 영상 안의 위치 (`MH_SnS_01 / F37`)
- **애니 프레임**: 만들고 있는 애니메이션의 타임라인 (프로젝트 설정 `anim_fps`, 기본 30)

프레임 간격은 둘 다 보여준다: `F4 → F11 = 7f (60fps) = 3.5f (30fps) (0.117s)`.
- 표기 규칙: **`@N`은 Maya 타임라인 위치 전용**(카드 아래 `@7`, 헤더의 `시작 @1`), fps는 항상 `30fps`로 쓴다. 한 화면에서 `@7`(위치)과 `@30fps`(비율)가 섞여 뜻이 흐려졌다.
- 열린 프로젝트의 애니 fps는 **보기 → 애니 fps**에서 바꾼다(설정의 값은 새 프로젝트 기본값). Hold는 애니 프레임 수 그대로 두고 초만 다시 계산한다.

### 1.3 시퀀스 타이밍을 하나로 통일
초안에는 "포즈 사이 타이밍(6f → 4f)", "Flipbook 표시 시간", "Maya 마커 절대 프레임"이 따로 있었다. 이걸 **하나의 값**으로 합친다.
- 각 시퀀스 아이템은 `hold` = **다음 포즈까지의 애니 프레임 수**를 가진다.
- 절대 프레임 = `start_frame + 앞 아이템들의 hold 합`.
- Board의 `6f →`, Flipbook 재생 속도, Contact Sheet의 Duration, Maya 마커가 모두 이 값에서 나온다. 한 곳을 고치면 전부 맞게 바뀐다.

### 1.4 Phase(역할)와 Tag 분리
- 키포즈는 **Phase 1개**(Anticipation, Contact …)와 **Tag 여러 개**(질풍참_준비, 방패 …)를 가진다.
- Phase는 **고정 색상**을 가진다 (목업의 주황/빨강/보라/초록). 라이브러리 필터 칩, Comparison Board의 열, Sequence 카드 색이 전부 Phase 기준이라 어디서 봐도 같은 의미다.
  - 대표 4색(Anticipation 주황, Contact 빨강, Follow-through 보라, Recovery 초록)은 고정하고, 빨강은 Contact 하나만 쓴다. 나머지는 서로 CIEDE2000 거리 12 이상(`tests/test_phases.py`) — Attack·Active·Contact가 거의 같은 빨강이라 Attack 구간이 Contact로 읽히던 문제.
  - Phase 색 위의 글자는 `phase_text_color()`: 상대 휘도 0.3 초과면 어두운 글자, 아니면 흰 글자 → 어느 Phase든 대비 3:1 이상.
- 초안의 "Motion / Weapon 필터"는 **소스 정보**(`origin`: 게임명, 소스 Tag)와 **키포즈 Tag**로 처리한다. 별도 필드를 늘리지 않는다.
- Comparison Board(2차)는 `소스 × Phase`로 자동 구성되므로 추가 입력이 필요 없다.

### 1.5 드로잉은 벡터로, 원본은 깨끗하게
- 드로잉은 선 데이터(점 좌표, 색, 두께)로 저장한다. 좌표는 **원본 이미지 기준 0~1 정규화** → 줌, Mirror, 해상도가 바뀌어도 맞는다.
- 저장 위치: 소스별 **프레임 드로잉**(그 프레임에서만 보임) + **가이드**(전 프레임에 보임. 예: 지면선, 기준 높이).
- 지우개는 **선 단위 지우기**(선을 건드리면 그 선 삭제). 벡터 방식에 더 맞고 실사용에서도 빠르다.
- 키포즈 PNG는 **드로잉 없는 원본 프레임**으로 저장하고, 드로잉은 표시/Export 때 합성한다(Contact Sheet에서 켜고 끌 수 있음).

### 1.6 Mirror는 보기 설정
- 소스별 Mirror(플레이어 보기), 키포즈별 Mirror(라이브러리/시퀀스/Export에 반영). 원본 파일과 PNG는 건드리지 않는다.

### 1.7 포즈 연결 검토 (초안 #23)
- 데이터에 `attrs`(예: `lead_foot: L`, `weight_foot: R`) 칸만 미리 둔다. MVP에서는 메모로 쓰고, 2차에서 시퀀스 카드에 L/R 배지를 띄워 앞발이 갑자기 바뀌는 곳을 눈에 띄게 한다.

### 1.8 Undo는 하나의 스택
- 드로잉, 키포즈 추가/삭제, 태그 수정, 시퀀스 편집이 전부 같은 Undo 스택에 쌓인다. Ctrl+Z는 "마지막으로 한 일"을 되돌린다.

### 1.9 Maya 옆에서 쓰기
- **Focus 모드**(Tab): 라이브러리/시퀀스를 숨기고 뷰어만 표시.
- **항상 위**(Ctrl+T): Maya 위에 작은 창으로 띄워두기.
- 창 배치(도킹 위치)는 다음 실행 때 복원한다.

### 1.10 동료와 함께 쓰기
나 혼자 쓰는 툴이 아니라 **다른 애니메이터 동료도 쓰는 툴**이다. 그래서:
- **프로젝트 공유**: 동료 PC에서는 영상 경로가 다르다. 상대 경로로 자동 연결을 먼저 시도하고, 안 되면 "영상 다시 연결" 창을 띄운다. **영상이 없어도 라이브러리와 시퀀스는 보인다**(키포즈 PNG가 프로젝트 폴더 안에 있으므로). 프로젝트 폴더만 넘겨줘도 포즈와 시퀀스를 볼 수 있다.
- **UI 언어**: 한국어/영어 전환(설정, 재시작 후 적용). 첫 실행은 Windows 언어를 따른다. Phase 이름(Anticipation 등)과 애니 용어(Onion Skin, Mirror, Flipbook, Contact Sheet, Hold)는 애니메이터가 영어로 쓰는 말이라 한국어 UI에서도 영어로 유지한다.
- **설정 위치**: 설치판은 `%APPDATA%\aniREF`, 포터블판은 exe 옆 `data\` 폴더. 포터블은 USB나 공유 폴더에 두고 써도 설정이 따라간다.
- **오류 로그**: 로그 파일을 남기고 "도움말 → 로그 폴더 열기" 메뉴 제공. 동료가 GitHub Issue에 첨부할 수 있게.
- **단축키 사용자 지정**: 사람마다 습관이 달라서 우선순위를 올린다.
- **PC 사양 차이**: 프레임 캐시 크기를 그 PC의 램에 맞춰 자동으로 정한다.
- **업데이트 알림**: 시작할 때 GitHub에 새 버전이 있으면 알려준다(설정에서 끌 수 있음).

### 1.11 분석 보기 (2차 구현에서 정한 것)
- **Onion Skin**: 멈춰 있을 때만 앞뒤 프레임을 디코딩해 겹친다(재생 중에는 재생 우선). 이전 프레임은 따뜻한 색, 다음 프레임은 차가운 색. 겹칠 프레임 수(앞뒤 1~3, 앞만, 뒤만)와 진하기는 사용자 설정.
- **실루엣**: S를 누를 때마다 원본 → 고대비 → 실루엣(Otsu 자동 임계값) → 반전. 보기 전용이라 키포즈는 항상 원본 프레임으로 저장한다.
- **Motion Trail**: 소스마다 여러 궤적(`Source.tracks`: 이름, 색, 프레임→정규화 좌표). T 도구로 클릭하면 현재 프레임에 점이 찍히고 다음 프레임으로 넘어간다(끌 수 있음). 이동 거리, 가로·세로 이동, 최고 속도(px/프레임)와 그 프레임, 시작점에서 최대 거리를 **영상 높이 대비 %**로도 보여준다. 골반 궤적 = Root Motion, 검끝 궤적 = 공격 범위와 가장 빠른 순간.
- **타이밍 구간**: `Source.sections`(시작·끝 프레임, 역할 라벨). 루프 범위에 B로 만든다. 루프가 없으면 앞 구간이 끝난 다음 프레임부터(앞 구간이 없으면 직전 키포즈부터) 현재 프레임까지 — 구간끼리 경계 프레임을 두 번 세지 않고 이어 붙는다. 타임라인 아래 띠로 표시하고, 툴팁에 프레임 수·초·애니 fps 기준 길이.
- **포즈 연결 검토**: 키포즈 `attrs`의 `lead_foot`, `weight_foot`(L/R/B)를 Inspector에서 토글로 입력.

## 2. 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 언어 | **Python 3.10+** | Maya와 같은 언어. 마커 import 스크립트 등 Maya 쪽 코드를 같이 관리할 수 있음 |
| UI | **PySide6 (Qt 6)** | 네이티브 데스크톱, 도킹 패널, 단축키 체계, Drag & Drop. Maya도 Qt/PySide라 조작 감각이 비슷함 |
| 디코딩 | **PyAV (FFmpeg)** | 프레임 단위 직접 디코딩. mp4/mov/mkv/webm/avi, H.264/HEVC/VP9/AV1/ProRes 모두 지원 |
| 수치 | numpy | 프레임 버퍼 |
| 저장 | JSON | 사람이 읽을 수 있고 Maya 스크립트에서 바로 읽음 |
| 빌드 | PyInstaller (폴더 방식) | Python 설치 없이 실행. 한 파일(onefile)보다 실행이 빠르고 백신 오탐이 적음 |
| 설치 파일 | Inno Setup | 관리자 권한 없는 원클릭 설치 |
| 대상 OS | Windows 10/11 64bit | 동료 전원 Windows |

**웹/Electron을 쓰지 않은 이유**: HTML `<video>`는 시간 기준으로 탐색해서 프레임 정확도를 보장하지 못한다(초안의 핵심 요구와 충돌). WebCodecs를 쓰면 가능은 하지만 컨테이너 지원이 제한적이고 복잡도가 크게 올라간다. **Qt의 QMediaPlayer도 같은 이유로 쓰지 않는다.**

## 3. 프레임 정확도 설계와 검증 결과

### 방식 (`core/media/decoder.py`)
1. 파일을 열면 패킷만 훑어(디코딩 없이) 모든 프레임의 타임스탬프와 키프레임 위치를 기록한다 → **프레임 인덱스**.
2. 프레임 N 요청 → N 직전 키프레임으로 seek → N의 타임스탬프가 나올 때까지 디코딩.
3. N 직전 48프레임은 캐시에 저장 → **뒤로 한 프레임 이동**과 GOP 안 스크럽이 즉시 된다.
4. seek가 목표보다 늦게 떨어지면(Open GOP, 잘못된 키프레임 표시 등) 더 앞 키프레임에서 다시 시도한다.
5. 타임스탬프가 없는 파일은 전체 디코딩으로 인덱스를 만들고, 그래도 안 되면 처음부터 세는 방식으로 대체한다.
6. 폰 촬영 영상의 회전 메타데이터를 반영한다(FFmpeg 출력과 픽셀 단위로 동일함을 확인).

### 자동 테스트 (`tests/test_decoder.py`)
프레임마다 **자기 번호를 바코드로 새긴 테스트 영상**을 생성해서, 요청한 번호의 그림이 정말 그 프레임인지 확인한다.

| 테스트 영상 | 특징 |
|---|---|
| h264_bframes.mp4 | B-frame 3장, 표시 순서 ≠ 디코딩 순서 |
| h264_longgop.mp4 | 60fps, 키프레임 간격 250 (OBS/YouTube 스타일) |
| h264_opengop.mkv | Open GOP (앞 GOP를 참조하는 B-frame) |
| h264_vfr.mp4 | 가변 프레임레이트 (16/17/33/50ms 간격) |
| hevc.mp4 | H.265, B-frame 4장 |
| vp9_altref.webm | VP9 숨은 프레임(alt-ref) |
| prores.mov | ProRes 10bit 4:2:2 |
| mpeg4_bframes.avi | 타임스탬프가 빠진 프레임이 있는 옛날 AVI |
| mjpeg.avi | MJPEG |

각 영상마다 프레임 수, 무작위 seek, 순차 재생, 역방향 한 프레임씩 이동, 프레임 시간, fps/VFR 판정을 확인한다 → **전부 통과**.

### 성능 (1920×1080 60fps H.264, 키프레임 간격 250, 이 PC 기준)

| 항목 | 결과 |
|---|---|
| 열기 + 인덱싱 (20초 분량) | 34 ms |
| 순차 디코딩 | 316 fps (실시간의 5배) |
| 무작위 seek (캐시 없음) | 평균 157 ms |
| 뒤로 1프레임 | 보통 0 ms, 48프레임마다 한 번 약 280 ms |

- 긴 GOP 영상을 스크럽할 때는 초당 약 6장 → M1에서 **"드래그 중엔 가까운 캐시 프레임 먼저, 멈추면 정확한 프레임"** 방식으로 체감 속도를 높인다.
- 4K/고압축 영상이 느리면 **프록시(전체 키프레임) 변환** 옵션을 추가한다 (2차).
- 실제 레퍼런스 파일 점검: `aniref-probe <영상파일>`

- **왼쪽 툴 레일**: 포인터 / 펜 / 직선 / 화살표 / 원 / 지우개 / 색 / 두께. (2차에 Onion Skin, Motion Trail 추가 — 목업 3과 동일) 뷰어와 타임라인 옆으로 이어지고(재생 컨트롤은 아래에 전체 폭 — 레일 옆에 두면 창 최소 너비가 64px 늘어 Maya 옆 반 화면에 못 들어간다), 색과 두께는 한 줄에 셋씩 놓는다 → 1600×1000에서 실루엣까지 스크롤 없이 보인다. 더 짧으면 아래쪽에 흐려지는 띠로 "아래에 더 있음"을 알린다. 채운 알약 배경은 지금 고른 **도구** 하나에만 쓰고, 켜고 끄는 보기 토글(매 프레임 · 보이기 · Onion · 실루엣)은 켜지면 배경 없이 왼쪽 강조색 막대와 글자색으로만 표시한다 — 보이기는 기본으로 켜져 있어서, 같은 알약이면 레일에 늘 두세 개가 똑같이 칠해져 어느 게 도구인지 안 보였다.
- **소스 탭**: 목업 1의 Source Videos 패널 대신 탭으로 공간을 아낀다. 소스 목록 패널(썸네일, 길이, 해상도)은 Compare 모드에서 사용.
- **타임라인**: 프레임 눈금, 루프 구간(회색 괄호), 키포즈 ◆(Phase 색)와 사이 간격, 타이밍 구간 띠, 드로잉이 있는 프레임 표시.
- **시간 + 프레임 동시 표시**: `00:01.233 / F 37` (목업은 시간만 있어서 추가).
- **라이브러리**: 클릭 = Inspector에 표시, 더블클릭 = 그 소스/프레임으로 이동, 드래그 = Sequence Board에 추가. 머리글 오른쪽 끝에 비교 보드 버튼(보기 메뉴·C와 같은 동작, 아이콘·툴팁·체크 상태도 같은 것)을 둔다 — Phase를 붙인 보람이 비교 보드인데, 메뉴와 C 말고는 가는 길이 안 보였다. 키포즈가 있을 때만 보인다.
- **Sequence 카드**: Phase 색 헤더, 소스/프레임, 애니 프레임 위치(@7), 카드 사이 hold 값을 바로 수정(스크롤/입력). 목업 1처럼 `0.12s (3f)` 표시.
- 라이브러리, Inspector, Sequence는 **도킹 패널** → 위치 변경, 숨김 가능. 키포즈가 하나도 없을 때는 Inspector 칸을 접어 둔다.
- **Inspector**: 작은 미리보기(최대 72px, 그리드에서 이미 강조된 카드를 크게 반복하지 않는다. 어두운 바탕과 Phase 띠는 썸네일 크기만큼만 왼쪽에 — 독 너비 전체에 깔면 검은 여백이 빈 영상 칸처럼 보였다) → 한 줄 정보(영상 · 프레임 · 시간 · 이전 +22f …) → **Phase** → 이름 → 태그 → 앞발/체중 → 메모. 독 분할은 Inspector가 Phase·이름·태그까지 스크롤 없이 보이는 높이로 잡고, 그리드에는 카드 한 줄 이상을 남긴다. 접히는 선은 줄 경계(태그 칸 아래)에 두고, 그 아래에 필드가 더 있으면 아래쪽에 흐려지는 띠를 보인다 — 다음 줄(앞발) 칸의 윗부분만 잘려 보이면 잘림 버그처럼 읽혔다.
- **시퀀스 보드 빈 상태**: 키포즈가 있어야 "여기로 끌어다 놓으세요"와 키 안내를 크게 보인다. 프로젝트가 없거나 키포즈가 아직 없으면 흐린 한 줄만 — 뷰어의 "영상을 끌어다 놓으세요"와 주의를 나눠 갖지 않게.
- **보기 상태 배지**: 기본값이 아닌 보기 설정(Mirror, Onion, 고대비/실루엣/반전, 드로잉 숨김, 1x가 아닌 속도)은 OSD가 사라진 뒤에도 뷰어 왼쪽 위에 작은 알약으로 남는다. Focus 모드에서도 보인다 — 잊은 Mirror로 반대쪽을 애니메이션하는 일을 막는다.
- **창 크기**: Maya 옆 반 화면·1080p에 들어가야 한다. 툴 레일은 짧으면 스크롤, 가운데 페이지는 지금 보이는 페이지 크기만 요구, 시퀀스 보드 머리글의 버튼은 좁으면 아이콘만 남긴다.

### 6.2 Compare 모드 (2차)
목업 1 구성 그대로: **행 = 소스(origin), 열 = Phase**, 칸마다 해당 키포즈 후보. 칸을 체크하면 맨 아래 **FINAL** 행에 들어가고 그대로 시퀀스가 된다. 오른쪽 Pose Inspector에 Silhouette/Mirror 토글.
- 보드가 떠 있는 동안 키포즈 라이브러리 독은 숨긴다. 보드 오른쪽 미리보기가 이 화면의 Inspector이고, 라이브러리까지 열려 있으면 같은 포즈를 두 번 보여주면서 열을 잘라 먹는다. 보드를 닫으면 독은 열기 전 상태로 돌아오고, 보드에서 프로젝트나 앱을 닫아도 그 상태로 기억한다.
- 포즈 행은 **한 줄 단위로 스크롤**하고, FINAL 위에 온전히 들어가는 줄만 그린다(남는 띠는 비워 둔다). 아래에 줄이 더 있으면 FINAL 바로 위에 흐려지는 띠와 "▼ 영상 n개 더"를 보인다 — 반쯤 잘린 줄은 빈 칸처럼 보였다. 무엇을 세는지 이름을 붙인다(같은 화면에 키포즈 수·고른 수도 있다).
- 열(Phase) 칩은 제목 줄에 둔다. 따로 한 줄을 차지하면 바로 아래 열 머리글을 되풀이하면서 영상 한 줄을 "▼ 더"로 밀어냈다. 창이 좁아 제목 줄에 안 들어가면 그때만 둘째 줄로 내려 전체 폭으로 줄바꿈한다.
- **Esc는 언제나 플레이어로 돌아간다**(앱의 다른 곳과 같다). 고른 것은 세션 상태라 닫아도 남고, 모두 해제는 되돌리기가 안 되므로 명시적인 버튼으로만 한다.
- 보드의 키(이동·고르기·플레이어에서 보기·시퀀스 만들기·열 옮기기·크기·돌아가기)는 `shortcuts.BOARD_KEYS["compare"]` 한 표에서 정의하고, 보드가 그 표로 키를 처리하며 툴팁·아래 키 안내·`?` 오버레이·단축키 전체 페이지·설명서가 모두 그 표를 읽는다.

| 장치 | 언제 보이나 | 하는 일 |
|---|---|---|
| 시작 화면 | 프로젝트 없이 켰을 때 | 가장 빠른 시작("영상 불러와서 시작"), 전체 작업 흐름(아직 안 되는 단계에만 **준비 중** 칩), 최근 프로젝트, 3분 가이드 |
| 빈 화면 안내 | 영상이 없을 때, 영상을 못 찾을 때, 못 열 때 | 지금 할 일과 버튼 (불러오기 / 다시 연결 / 탭 닫기), 관련 단축키 |
| OSD | 키를 누를 때마다 | 뷰어 위에 결과를 1초간 표시 (`루프 켜짐 F281 – F341`, `속도 0.25x`). 키보드만 쓸 때 무엇이 바뀌었는지 바로 확인 |
| 툴팁 | 버튼에 마우스를 올릴 때 | 기능 이름 + 단축키 |
| 상태 표시줄 | 항상 | 지금 화면에서 되는 단축키만: 시작 화면은 불러오기·프로젝트 열기·설명서·단축키, 작업 화면은 재생·1프레임·루프·키포즈·그리기 도구. 시퀀스 보드 카드 줄이 키를 가져가면 안내도 따라 바뀐다(카드 선택·Hold·빼기·Esc 플레이어로) — 그동안 ← →는 프레임이 아니라 카드를 고른다. 비교 보드에서는 숨긴다(보드에 자체 키 안내가 있음) |
| `?` 오버레이 | `?` | 모든 단축키를 화면 위에 겹쳐서 표시, Esc로 닫기 |
| 사용 설명서 | F1, 도움말 메뉴 | 별도 창(Maya처럼 옆에 띄워둘 수 있음). 목차와 검색, 10개 페이지: 3분 가이드, 화면 구성(번호 그림), 재생, 루프, 프레임 번호, 보기, 프로젝트, 단축키 전체, 문제 해결, 로드맵 |

- **단축키는 한 곳에서 정의**(`ui/shortcuts.py`)하고 메뉴·툴팁·오버레이·상태 표시줄·설명서가 전부 거기서 읽는다. 설명서 본문도 키를 직접 쓰지 않고 `{a:loop_in}`처럼 참조한다 → 단축키를 바꿔도 안내가 틀어지지 않는다.
- 기능을 추가할 때마다 설명서 페이지, 로드맵 상태, 시작 화면 작업 흐름 칩을 같이 갱신한다. 테스트가 설명서의 단축키·페이지 링크·한/영 문구 누락을 검사한다.

## 8. 배포

**공개 GitHub 저장소 + GitHub Releases.** 동료는 GitHub 계정 없이 Releases 페이지에서 받는다.

| 파일 | 용도 |
|---|---|
| `aniREF-<버전>-portable.zip` | 압축 풀고 `aniREF.exe` 실행. 설치 없음, 설정은 폴더 안에 저장 |
| `aniREF-<버전>-setup.exe` | 원클릭 설치. 관리자 권한 불필요(사용자 폴더에 설치), 시작 메뉴 등록, `.aniref` 더블클릭으로 프로젝트 열기, 제거 지원 |

- **자동 빌드**: `v0.2.0` 같은 태그를 push하면 GitHub Actions(Windows)가 테스트 → PyInstaller 빌드 → zip·설치 파일 생성 → Release 업로드까지 한다. 로컬 PC에 빌드 환경이 없어도 된다.
- **Maya 스크립트**도 zip과 설치 폴더에 같이 넣는다. `install_aniref.mel`을 Maya 뷰포트에 끌어다 놓으면 셸프 버튼이 생긴다.
- **Windows 경고**: 코드 서명이 없어서 처음 실행할 때 SmartScreen 경고가 뜬다. README에 "추가 정보 → 실행" 안내를 넣는다. 사용자가 늘면 서명 인증서(유료)를 검토한다.
- **라이선스: GPL-3.0.** 함께 배포하는 FFmpeg(PyAV 포함본)에 GPL 라이브러리(x264, x265)가 들어 있어서 GPL이 가장 깔끔하다. PySide6(LGPL)는 폴더 방식 빌드라 라이브러리 교체가 가능해 조건을 만족한다.
- **버전 규칙**: `0.x` 동안은 기능 단위로 올린다. 프로젝트 파일 형식이 바뀌면 `version`을 올리고 옛 파일을 자동 변환한다.
- **크기**: 대략 150MB 안팎 예상(필요한 Qt 모듈만 포함). 첫 빌드 때 실측해서 갱신.
